# 🌳 objTree

Процедурный генератор деревьев на C++17. Строит объёмные 3D-модели стволов, ветвей и кроны и экспортирует их в `.obj` — открывается в Blender, Maya, Houdini, любом 3D-редакторе.

## ✨ Возможности

- 🌲 **Пресеты в JSON** — сосна, берёза, дуб, ива. Правь файл — получай новое дерево, без пересборки.
- 🎲 **Детерминированный сид** — одинаковый `seed` даёт одинаковое дерево (для отладки и сравнения).
- 🧬 **Разное ветвление** — от 1 до 4 детей на узел, с распределением по толщине родителя.
- 🌀 **Без перекрутов** — параллельный перенос фрейма вдоль ствола, грани не закручиваются.
- **Провисание** (`droop`) — тонкие ветви клонятся вниз, для «плачущих» форм.
- 🌴 **Голый ствол** (`trunkHeight`) — крона начинается выше, как у сосны.
- 📐 **Полный контроль** — 20 параметров: радиус ствола, длина сегмента, углы, плотность кроны.

## 🚀 Быстрый старт

### Сборка

```bash
git clone <repo-url> objTree
cd objTree
cmake -B build/release -DCMAKE_BUILD_TYPE=Release
cmake --build build/release
```

Бинарь лежит в `build/release/bin/objTree_cli`.

### Запуск

```bash
./objTree_cli presets/oak.json     # → mesh.obj
```

Открой `mesh.obj` в Blender (`File → Import → Wavefront (.obj)`).

Если указанный JSON не найден — он будет создан с настройками по умолчанию. Удобно начинать с нуля:

```bash
./objTree_cli my_tree.json         # создаст my_tree.json с дефолтами
# ... редактируешь my_tree.json ...
./objTree_cli my_tree.json         # читает твои настройки
```

## 🌿 Пресеты

Готовые конфиги лежат в `presets/`. Каждый — самодостаточный JSON, можно передавать как аргумент.

| Пресет | Форма | Силуэт |
|---|---|---|
| 🌲 **`pine.json`** | Высокий голый ствол до ~50 ед., потом почти горизонтальные мутовки | Ярусный, узкий |
| 🌳 **`birch.json`** | Высокий тонкий ствол, ажурная крона, стремящаяся вверх | Вытянутый овал |
| 🌰 **`oak.json`** | Короткий мощный ствол, широкое ветвление с низу | Приземистый, плотный |
| 🌾 **`willow.json`** | Короткий ствол, густая крона, длинные провисающие ветви | Плакучий «водопад» |

Сравнить все сразу:

```bash
for p in pine birch oak willow; do
    ./objTree_cli presets/$p.json && mv mesh.obj $p.obj
done
```

Открой четыре `.obj` в одном окне Blender — разница видна сразу.

## ⚙️ Параметры

Все поля опциональны: отсутствующее в JSON — остаётся дефолтным. Это позволяет делать «минимальные» конфиги на 2–3 поля для экспериментов.

### Геометрия

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `seed` | `0` | Сид RNG. `0` → случайный на каждый запуск. Ненулевой → воспроизводимо. |
| `pointsPerRadius` | `60` | Точек на единицу радиуса окружности (плотность меша). |
| `startRadius` | `2.0` | Радиус основания ствола. |
| `coeffLenByRadius` | `30.0` | Длина сегмента = `радиус × coeff`. Больше — длиннее сегменты. |
| `radiusMax` | `2.5` | Условно «толстый» радиус — для расчёта асимметрии детей. |

### Ветвление

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `countBranchMin` | `1` | Минимум детей на узел. |
| `countBranchMax` | `4` | Максимум детей на узел. |
| `countBranchMean` | `2.0` | Среднее число детей. |
| `countBranchStd` | `0.8` | СКО числа детей. |
| `spreadThick` | `0.20` | Разброс радиусов детей **толстого** родителя. `0` — все равны. |
| `spreadThin` | `2.00` | Разброс радиусов детей **тонкого** родителя. Больше → один «лидер». |

### Разброс направления

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `thetaMin` | `0.0628` (0.02π) | Минимальный угол от родителя. Мало → ветви почти параллельны оси. |
| `thetaMax` | `1.4137` (0.45π) | Максимальный угол от родителя. Много → почти горизонтальные ветви. |
| `thetaJitter` | `0.2618` (π/12) | Шум угла конуса. Больше → «рванее». |
| `dominanceK` | `1.2` | Насколько сильно тонкая ветвь уходит вбок от родителя. |
| `tangentialSpread` | `0.08` | Тангенциальный шум нормали. Больше → «корявость». |
| `tangentScale` | `1.2` | Изгиб Hermite-кривой между узлами. Больше → изогнутее. |

### Дополнительные формы

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `trunkHeight` | `0` | Высота голого ствола (в единицах Y). Ветвление начинается выше. |
| `droop` | `0` | Провисание тонких ветвей. `0.5–0.7` — «плакучая» форма. |

### Сегментация

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `coeffCountSeparate` | `6` | Промежуточных колец на сегмент. Больше → глаже изгиб. |
| `coeffSeparationM` | `0.5` | Средняя доля от `radius × coeffLenByRadius` на сегмент. |
| `coeffSeparationD` | `0.3` | СКО длины сегмента. |

## 🧠 Как это работает

**Идея.** Каждая ветка — это последовательность окружностей, посаженных на кривую Эрмита между родительским и дочерним узлами. Окружности обшиваются треугольниками, узлы ветвления раскидывают несколько дочерних веток в конусе вокруг родительской оси.

**Три нетривиальных решения:**

1. **Параллельный перенос фрейма.** Каждая окружность несёт локальную ось `xAxis`. Ось следующей окружности получается **минимальным поворотом** из предыдущей (`parallel_transport`), а не пересчётом от мировой оси X. Без этого грани перекручиваются.

2. **Одна случайная фаза на узел.** Все дети одного узла лежат в одной плоскости (свойство конуса). Плоскость поворачивается на случайный `phi0`, чтобы дерево было объёмным, а не плоским.

3. **`droop` взвешен на «тонкость».** Тонкая ветвь провисает сильнее, толстая — почти нет. Формула: `branchDir.y -= droop × (1 − r_end/r_root)`. Ствол не наклоняется никогда.

**Общий поток:**

```
TreeConfig (JSON)
     │
     ▼
 grow_tree()
     │  stack-based DFS
     │  ├─ get_child_circle() → радиусы детей
     │  ├─ конусное отклонение + perturb
     │  ├─ parallel_transport фрейма
     │  └─ separate_branch() → промежуточные кольца
     ▼
 Branch tree
     │
     ▼
 create_mesh()
     │
     ▼
  mesh.obj
```

## 💡 Советы

**Воспроизводимость.** Понравилось дерево — скопируй сид из консоли в `tree.json` (`"seed": 12345678`). Теперь этот же результат воспроизводится всегда.

**Эксперименты без правок C++.** Меняй один параметр, перезапускай, смотри. Быстрее всего:

```bash
./objTree_cli presets/oak.json && blender oak.obj &
```

**Хочешь ещё шире.** Увеличь `thetaMax` до `1.5` и `countBranchMax` до `4`. Или начни с `oak.json` — он самый «широкий» из коробки.

**Хочешь выше.** Увеличь `coeffLenByRadius`, но пропорционально и `startRadius`, иначе ствол умрёт до `trunkHeight`. Для одиночной ветки с длинным стволом попробуй `{"startRadius": 3, "trunkHeight": 80, "coeffLenByRadius": 40}`.

**Слишком плотно, тормозит.** Снизь `pointsPerRadius` до 30–40 и `coeffCountSeparate` до 4. Меш уменьшится в 4–6 раз, на форму почти не повлияет.
